## 1. 규모 (OT 라이브 발화, 2026-09-09)

- 예선 참가 **4,000명 이상**. 전국 10대~60대, 비개발자부터 전문 엔지니어까지
- 결선 진출 **50팀**
- 예선 제공 크레딧 총액 **44,750,000**
- Q&A 는 디스코드로 접수. OT 녹화본은 같은 링크(`bit.ly/mabc2026-final-ot`)에서 VOD 로 제공
- 플랫폼 선택 가이드(운영진 발화): 양쪽 다 Solar Pro 4 를 쓰며, **개발이 익숙하면 Hermes Agent 를 권장** → 우리 선택과 일치
- ❌ **미확인으로 종결**: "$30 이 정가 환산 $200급"이라는 발화는 공식 문서에 근거가 없다. 실제 프로모션 할인율(90%)로 역산하면 $300 상당이라 "$200" 과 맞는 계산 경로가 없다. **다만 크레딧 자체는 넉넉한 것이 맞다** — $30 = 약 5.7억 토큰(90% 할인 구간). ⚠ **진짜 병목은 크레딧이 아니라 rate limit(Tier 0 = 100 RPM / 50,000 TPM)** 이고, 프로모션 할인은 **2026-09-11 UTC 에 90% → 70% 로 전환**되어 결선 기간과 겹친다. 근거·환산 과정 → `research/2026-09-09-solar-pro4-pricing.md`
- 대회 지원 사항: 결선 OT 사전 교육(**강의자료 별도 배포 예정**) · 담당 멘토 기술 Q&A(디스코드 상시) · 기획 멘토링(~9/12) · 개발 멘토링(~9/15)

## 4. 심사 기준 (사전 90 + 현장 10 = 100)

| 평가 항목 | 배점 | 핵심 질문 |
| --- | --- | --- |
| Project Impact (문제 정의·기획) | 25 | 문제 정의가 타당하고 실용적이며, 그에 맞는 기획이 이루어졌는가 |
| **예선 스킬 활용도** | **30** | 예선 대표 스킬이 서비스에서 **중심 역할**을 하며 **안정적으로 동작**하는가 |
| Technical Implementation (사용성) | 15 | 처음 방문한 사람도 직관적으로 쓰고, 핵심 기능이 목적에 맞게 동작하는가 |
| Innovation & Creativity (독창성·확장성) | 20 | 사용 전후 효과가 뚜렷하고 문제 해결 방식이 새로운가 |
| 발표 전달력·논리 (현장) | 10 | 발표의 전달력과 내용 전달의 논리성 |

- 사전 심사 90점 = 위 4개 항목 / 현장 발표 10점 = 발표 전달력
- **제출 필수 요건 미충족 시 사전 심사 대상에서 제외**
- 완성도는 **심미성이 아닌 사용성** 관점 — 핵심 기능의 명확한 동작, 이해 가능한 화면 구성. 개발 플랫폼 차이로 인한 유·불리 없도록 함(규정 제12조 1항)
- **동점 시 먼저 제출한 팀 우선** (규정 제5조 7항 준용)

## 5. ⚠ 개발 환경 제한 — 실격 조건 (규정 제9조)

1. **LLM 은 Solar Pro 4 만.** 타 모델(Claude·GPT·Gemini 등) 외부 호출 시 실격. 플랫폼 자체 fallback(이미지 입력 등)은 예외
2. **AI 개발 도구는 ① 타임리(지정 MABC 워크스페이스) ② Solar Pro 4 연동 Hermes Agent 두 가지로 한정.** 그 외 외부 AI 코딩 에이전트·어시스턴트(**Claude Code · Cursor · Codex 등**)를 개발 과정에 사용하는 행위는 **부정행위**
3. FAQ 는 여기서 한발 더 나간다 — "ChatGPT·Claude 로 **아이디어·프롬프트만** 도움받는 것도 안 됨. 서비스 런타임과 **개발 과정 전반**에 Solar Pro 4 만 허용. 외부 LLM 을 아이디어·프롬프트·코드 작성에 활용한 내역이 확인되면 부적격"
4. **코드 편집기로 직접 작성·수정하는 것은 허용.** 단 그 내역이 검증 과정에서 **설명 가능**해야 한다
5. **MCP 허용.** 모델이 아닌 공개 외부 API(지도·날씨·공공데이터 등) 허용 — 저작권·출처 표기 준수. **타 LLM 을 활용한 합성데이터 제작은 불허**
6. API 키·인증정보를 소스코드·배포물에 노출 금지. 노출로 인한 크레딧 손실은 참가자 책임
   - 단 FAQ: 키 노출은 **즉시 실격이 아니라 감점 없는 1회 수정 요청**. 기한 내 미수정 시에만 감점·부적격

### 개발 기록 수집·대조 (규정 제10조)

- 참가자는 **결선 기간 2026-09-09 ~ 2026-09-16** 동안 타임리 및 Hermes Agent(업스테이지 콘솔 API)를 통한 **대화·입출력 기록이 부정행위 검증 및 심사 목적으로 수집·열람되는 것에 동의**해야 한다
- **Hermes Agent 사용자는 별도의 데이터 적재 동의를 완료해야 하며, 미동의 시 결선 참가 불가**
- 운영진이 **제출 PRD·소스코드와 개발 기록을 대조**해 정합성을 검증한다. **개발 기록으로 설명되지 않는 코드·기능은 규정 외 도구·모델 사용으로 추정**하며, 소명하지 못하면 부정행위로 판정
- 재현·검증 요청(소스 제공·시연·기록 확인) 불응 시 실격(제18조 5항)

### 그 밖의 그라운드룰

- **예선 당선 스킬을 서비스 핵심 로직에 필수 포함.** 서비스화를 위한 수정·확장은 허용, 변경·고도화 내역은 PRD 스킬 매핑에 기재. 본인이 만든 스킬 여러 개를 함께 쓰는 것도 가능
- **예선에 제출하지 않은 새 스킬로 갈아타는 것은 불가**
- 타인 스킬 무단 사용 → 도용·표절 실격
- **독립 배포 공개 URL 필수 — 타임리 워크스페이스 공유 링크는 불인정("미제출" 처리)**
- 배포 플랫폼 자유(교육·가이드만 Vercel 기준). 심사 시점 접속 불가 시 평가 제외
- GitHub 저장소 **Public** 필수, 최종 코드 전부 push. 제출 이후 배포본 변경 불가, 심사 종료까지 동일 유지
- 9/19 현장 **팀당 1인 이상 필참**, 미참석 시 평가 제외
- 결선 팀원 추가·교체·탈퇴 불가 (운영진 사전 승인 예외)

- **플랫폼 중복·변경 불가** — 9/9 이후에는 크레딧 미사용이라도 변경 불가. 팀 내 혼합 발급도 불가
